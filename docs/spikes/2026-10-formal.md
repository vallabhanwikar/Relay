# Spike: formal counterexamples from Z3 and OpenJML (weekend 1)

**Question:** can Relay produce a real formal counterexample, and a real proof, from both Z3
and OpenJML?

## Z3 schema compatibility: done, and past spike quality

This grew straight into the Phase 1 prover (`relay-formal`) rather than a throwaway spike.

| Check | Result |
|---|---|
| New enum value read by the consumer | COUNTEREXAMPLE `{"status": "PARTIALLY_REFUNDED", ...}`, exact |
| Same change, consumer has a default branch | PROVEN |
| Removed field nobody reads | PROVEN |
| `multipleOf: 0.1` vs `0.01` | Decided in milliseconds after re-encoding; the naive encoding timed out at 30 s |
| Differential fuzz, 7,500 random schema pairs (5 seeds × 1,500) | No unsound proof, no fabricated counterexample |
| Full test suite (44 tests) | About 3 s, green on Z3 4.14.1 (the pinned version) and 5.1.0 |

**Found during the spike:**

- *Mixed real/integer encodings time out.* `isInt(x / step)` is fine for one schema, but the
  comparison of two schemas (`0.1` vs `0.01`, even `5` vs `10`) made Z3 give up. The fix keeps
  both sides on one integer `t = x · D`.
- *Vacuity is a real risk.* A request usage that forgot a required field made the producing
  side contradictory, which would have "proven" everything. There is now a guard, and usage is
  completed automatically.

## OpenJML: ready to run, not yet run

`sandbox-runner/openjml/` builds OpenJML 21.0.28 into a container with no network.
`relay-formal/examples/openjml/` holds the doc's discount example in a buggy and a fixed
version. The workspace these files were written in could not download the OpenJML release, so
this half still needs a local run:

```bash
sandbox-runner/openjml/run-esc.sh relay-formal/examples/openjml/Discount.java
# expect: postcondition violation with percentage > 100
sandbox-runner/openjml/run-esc.sh relay-formal/examples/openjml/DiscountFixed.java
# expect: no warnings
```

Record the actual output, timings and any friction here. If `DiscountFixed` comes back
UNPROVEN, the likely cause is the non-linear `price * percentage`. Try OpenJML's solver options
before changing the example.
